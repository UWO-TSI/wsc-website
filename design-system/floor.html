Partners

One tier group, because the sponsors table has no tier column and supabase/ is off limits. The bar and label are --gold, not --accent: a sponsor's standing has to read the same on every page. Scale comes from display_order, the lead tile spanning two columns. The whole wall is --logo-ground, the third fixed mark, a constant near-black. A sponsor's logo is supplied artwork we may not redraw and most of them are light-on-transparent, so on the white page ground they washed out. The ground is the panel, not a patch behind each mark: per-logo tiles read as a grid of separate dark patches. Ink on it is --on-logo-ground. A sponsor with no file gets their name set in the display face in the same cell rather than a redrawn mark or an empty frame. A sponsor with a link is an anchor and scales slightly on hover; one without is inert.

13  SkeletonsA thing that has to load reserves its own space and fills in.

A skeleton is built to the shape of the thing it stands in for, not to a generic box. That is the whole point: a centred spinner has a different shape from the content that replaces it, so the page jumps the moment the query resolves. Here the row skeleton carries the same 30px index, name, meta and 34px avatar slot as a real ledger row, at the same rest padding, so the list occupies its final height from the first paint.

The fill is derived from currentColor, so one rule is correct on every slab tone without a variant per ground. Widths vary down a column, because identical bars read as a loading graphic rather than as names. The sweep is the one thing in the system that animates at rest, and it is deliberate: a static grey block reads as broken layout. It stops under reduced motion, and once the content behind it has loaded.

An image frame goes further: it holds its aspect ratio from the first paint, keeps the skeleton mounted behind the picture, and waits for the bytes before running Clip Reveal. Unmounting the skeleton on load leaves one frame where it is gone and the image is still clipped, which shows as a flash of empty.

An empty photo slot is the same frame with nothing to load: the skeleton surface with its sweep stopped takes the photo's place, at the slot's own aspect, and runs the same Clip Reveal a photo runs, with no label. Visitors see it too, so the layout and the motion read before the club has uploaded a photo. The bare section card above shows it running.

One tier per role, in role order. Every portrait is the same size in every tier; only the order shows rank. No heading names a tier: the title under each name gives the role.

Each tier is a centred row that wraps, so a short last row is centred under the full rows above it. The gap between tiers is larger than the gap between rows inside one.

No cell is a card: no fill, no shadow, no border, no hover, no link. These are people, not controls. Headshots are always visible here, unlike on the event ledger, because a profile picture is the content. A missing one falls back to initials on --sunken, which is a designed state.

Every editor in the content manager is a Save bar over a list. The bar is the title, a status line, and one Save. Save sits disabled on --sunken until something changes, reads Save all changes while edits are pending with Discard beside it, and reads Saved for two seconds after writing. Only the button says so; the list under it updates in place and never drops to a loading state.

A reorderable row is a ledger row on --sunken with a grip first: three lines, the same mark as the menu toggle, 36px square. Only the grip starts a drag, so the chip and the actions stay clickable, and it takes the arrow keys one step at a time. The held row lifts to --sh-3 and its neighbours slide on --d-move / --e-move, the budget for anything changing position. No new sequence: this is the move row, not a thirteenth.

Leaving an editor with edits pending asks once, Stay or Discard and leave, in the same dialog shape as delete. It never traps anyone.

Every field of a row is inline, in the Field shell, sized to its text; the column's limit in the database is the most it accepts. InlineSelect (role and area) shows its chevron at rest; the area list ends with Add an area, which turns into a text input in place and refuses a name that matches an existing area ignoring case. InlineNumber is the figure's number in a Field as wide as the number. VisibilityChip is a toggle button, Visible or Hidden, as wide as the longer word. StateChip reserves its slot and shows Unpublished or Will be removed. Grip is card 15's grip on a 36px disc at the item's corner: drag by mouse or touch, or move one place with the arrow keys, announced as "Moved Mei Chen to position 2 of 5". The held item lifts to --sh-3 and neighbours move on --d-move, --e-move. AddTile is the last cell, the empty photo-slot surface with a tertiary label, and arrives with Clip Reveal when an add moves it along; at the list's cap it stays in place, disabled, and pressing it says why in the tray. Options, a tertiary button and the last control of each row, moves focus to the row's controls in the tray (the link address, Remove); Escape, Enter in the link address, or Tab past either end of the tray comes back to it. Every row field is named with its row ("Name, Mei Chen"). A row whose date or role changes keeps its place until focus leaves the list, then moves once. Remove is in the tray; a removed item stays with Will be removed until Publish, then leaves on --d-move, --e-exit and its neighbours close the gap on --e-move. The event ledger has no grip, because events are ordered by date.

The bar has one fixed size at each width. The tray is the only region whose content changes, and it never grows: it holds the name and count of the focused field, a link address, a photo's minimum width, a list row with its Remove, a new area, confirmations and results. There are no dialogs. It is a grid of label, body and actions: on phones the actions share the label row and the body has three lines (110px); from 900px the actions end the body row (76px). Both heights are set in em of the tray's text plus its fixed padding, so text-only zoom grows the tray with its text. The Publish button is wide enough for Publish 99 changes, so its label changes to Publishing and Published in place without moving the bar.

Layers, back to front: the lit ground, moving grain, the ribbon, the dot matrix. A dot is --tex-dot across, a ribbon line is --tex-dot thick and solid, and both repeat every --tex-pitch. The ribbon is drawn once per size and the same size always draws the same ribbon. The grain moves six times a second and stops only under reduced motion. The ribbon and the dots never move. In the app this is <Slab tone="accent" texture="sweep">, inverse or accent only.

ExtendingWhat to do when the thing you need is not in here.
1Look first

Read this page before writing CSS. Most new components are an existing one re-composed.

2Spend tokens only

Every colour, radius, shadow, duration and easing comes from a token. No new hex, no new number.

3Reuse a sequence

Pick from the eleven named sequences. A new one is a design decision, not an implementation detail.

4Add it back

Ship the component and its card on this page in the same change. If it is not here, it does not exist.

Do
  • Compose from Slab, Button, Field, Row
  • Match the nearest component's padding and radius
  • Give it a focus ring and check it on every tone it can be placed on
  • Name the sequence it uses
Do not
  • Invent a colour, a radius or a duration
  • Add a border to separate anything
  • Write a one-off animation
  • Ship it without a card on this page
