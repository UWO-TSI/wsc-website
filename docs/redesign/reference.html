Purpose

Who edits, and what they need to see

Who

The president and the VP Marketing. Neither is a developer. They edit a few times a month, often from a phone, usually right after an event or a change on the exec team.

The job

Keep the site current: add an event, replace a photo, change a heading, add or remove an executive, update a sponsor.

What they must understand

Which part of the site a change affects, what it will look like, and whether visitors can see it yet.

Primary action

Publish. Everything else on the screen is the site itself.

The problem today

The current portal is a separate set of forms. Fields are named by position, such as "Strip, left" and "Heading, line 2", so the editor has to work out which part of the site each field controls. The result is only visible after saving and opening the site in another tab.

The rules for edit mode

Typing changes the text inside a field. It never changes the size of the field.

Each field is sized to its longest allowed value at the current screen width: one-line fields by width, paragraphs and headings by height. The database already stores that limit for every string (site_content.max_length), so the size comes from the same numbers that stop over-long input.

The page reads as a form that is already filled in.

Every text field on every page has a tinted fill and inner padding at rest, so you can see where it starts and ends without hovering. A heading of two lines is one field; Enter starts the second line. Because fields are only as wide as their longest value, neighbouring fields keep space between them. Every selector shows its chevron. Every photo shows Replace photo or Add photo, and clicking it opens the device's own file picker: Finder on a Mac, File Explorer on Windows, the photo library on a phone. Hover changes only the cursor.

Allowed move: reorder

You drag a person or event by its grip, with a mouse or a finger, or move it with the arrow keys. Neighbours slide to their new places on the move timing.

Allowed move: add

The new item takes the place of the Add tile, so nothing shifts. A fresh Add tile appears in the next cell.

Allowed move: publish

Removed items stay in place, marked, until you press Publish. Only then do they leave and the gap closes.

Allowed move: preview

Preview removes the fills and padding so you see the exact visitor layout. The section you were looking at stays at the same height on screen.

The flow

From sign-in to live

1Sign in

At /admin: Google, then the six-digit code from the authenticator app. Same as today.

2The site opens

Home page, in edit mode, with the edit bar at the bottom. There is no dashboard.

3Type and pick

Every heading, paragraph, button label, photo and person is already a field. Change it where it is.

4Check it

Changed sections carry an Unpublished chip and the bar counts them. Switch to Preview to see the visitor layout.

5Publish

Publish writes every change at once. Discard drops them all.

Motion

What moves in edit mode

Three moves, each caused by the editor. Everything that moves by itself is off. No new sequence is added.

MoveWhenSequence and timing
HoverAny field or photo.No motion. Fields already show their fill, so hover changes only the cursor.
ReorderA grip is dragged or moved with the arrow keys.Card 15 move row: held item --sh-3, neighbours --d-move, --e-move.
New Add tileAfter an item is added in the old tile's place.Clip Reveal, --d-arrive, --e-enter.
RemovalOnly on Publish, for items marked Will be removed.Leave on --d-move, --e-exit, then neighbours close the gap on --e-move.
Off in edit mode
  • Line Mask Reveal, Word Cascade, Slab Clip and Clip Reveal on scroll. Every section shows in its final state.
  • Counter Roll. Figures show their real value so they can be edited.
  • Row Expand on event rows. It changes padding on hover.
  • Magnetic Pull on buttons. A button you are typing into must not follow the pointer.
  • Marquee Drift. The partner strip shows as a static wrapped grid, the same as reduced motion.
  • The preloader curtain.
Kept
  • Button press scale, --d-tap, on buttons that are not being edited.
  • The Publish label changing in place: Publish 3 changes, then Publishing, then Published for two seconds.

Applied to westernsalesclub.ca
  • The one action is Apply to join, already the hero button and the label of home.cta.button_label. It goes in the nav pill at every width, the hero, the About section and a closing band on every page.
  • The second action is See events, which asks only for a look.

Changes to Floor this needs, separate from edit mode
  • An alignment rule in the README: selling sections centred, reading sections left-aligned.
  • Layout: a slab spans the full viewport width with no side gap, and keeps its --r-xl corners. Where two slabs meet they sit 2px apart. The 24px inset gutter around slabs is removed; content inside keeps the gutter as padding.
  • The nav pill gets a primary button. components.md currently lists only glyph, wordmark, links and the indicator.
  • A new token, --inverse-tile, for tiles inside an inverse slab, as used in the rules section above.
  • The signature texture as tokens and one utility: --grain, --grain-strength, --wave-strength and a textured class for loud slabs. Velvet for selling bands, velvet black for statement slabs. One hairline ribbon in a corner, grain across the whole slab, no gradients.
  • Focus ring on inverse and accent slabs in the slab's text colour, since --focus is velvet and does not show on the velvet-black ground.
  • On an inverse slab the primary button uses the page fill, the same exception Floor already makes for accent slabs.
One theme

White and velvet, everywhere

Afterhours, the near-black and gold theme, is removed. Every visitor sees Showroom whatever their device is set to. The brand reads as one colour pair on every page and in every screenshot, and every component is designed and checked once.

Removed from the app
  • The dark palette blocks in tokens.css and src/app/globals.css.
  • theme-toggle.tsx, theme-provider.tsx, src/lib/theme.ts, and the toggle in nav.tsx and admin-dashboard.tsx.
  • The blocking theme script in layout.tsx. It existed only to stop the wrong theme flashing on load.
  • color-scheme: light is set on the root, so a phone in dark mode still draws light form controls and scrollbars.
Changed in Floor
  • Rule 2, "the accent flips with the theme", becomes "the accent is velvet". Rule 5, "both themes ship together", is removed.
  • Theme Wipe, sequence 11, is retired. Floor keeps eleven sequences.
  • --gold stays as a fixed mark for sponsor tiers. --logo-ground stays near-black, because supplied logos are light artwork.
  • floor.html loses its theme toggle and its Afterhours swatches. The project CLAUDE.md headline rules are updated to match.
  • The inverse band is velvet-black on every device.

Publish model

When does a change go live?

Chosen Draft, then Publish
  • Edits change the page in your own browser only. Publish writes all of them together.
  • You can work across several pages and check them in Preview before any visitor sees them.
  • Cost: one draft store, read by the site content provider and by the shared list query hook. Chosen photos wait in browser storage until Publish.
  • A draft lives in one browser. A draft started on a laptop is not on your phone.
Save as you go
  • Each field writes when you leave it. No Publish button.
  • Less code: no draft store.
  • Cost: a half-finished change is live while you work on the next one, and Preview has nothing to show.

Access and screens

Keyboard, phones, both themes

  • Every field is labelled from site_content.label plus its section, for example "About, heading".
  • The field fill is the text colour mixed at 9 percent, so it shows on the page ground, raised slabs, the inverse band and inside buttons.
  • Tab order follows the page. The focus ring is drawn on the field's shell.
  • Grips move with the arrow keys and announce "Moved Amara Boateng to position 2 of 5".
  • The tray announces errors and publish results only.
  • The visibility chip is a toggle button with a pressed state.
  • On phones the bar keeps one fixed height with the tray on its own row. Pages get bottom padding equal to the bar so the footer stays reachable.
  • Inputs smaller than 16px make iOS zoom on focus. On touch screens the role and area selects use 16px.
  • Edit mode pages are not indexed. The edit code loads only after is_admin() returns true at the authenticator-code level.
Verification

How we check that nothing moves

  • Typecheck and lint on every step.
  • Unit tests for the draft overlay, the change count, the title builder, the two-line heading split and the reserved-size measure.
  • A stability test: a headless browser opens each page in edit mode at 375, 768 and 1280px, marks every persistent element, types the maximum length into every field, and fails if any marked box changes position or size. It also hovers and focuses each field and checks the same boxes.
  • The publish flow against the local Supabase stack, including a forced failure to check the partly-failed state.
  • Reduced motion, by eye, on the rendered pages.
Build order

Eight steps, each shippable

Removing the dark theme comes first, because it shrinks every later step to one palette. The sales direction is its own track. It changes Floor and the public pages, and can ship before or after edit mode.

  1. MigrationsRoles and areas, drop year of study, remove the access lifetime. The current dashboard gets the matching form changes, so it keeps working until step 8.
  2. Floor card 16Field, inline text, heading, paragraph, label and select, chips, grip, Add tile, edit bar and tray, before any app code.
  3. Draft storeOne store for text, photos and list rows. The site content provider and the list query hook read through it.
  4. Edit mode switchSign-in at /admin opens the site in edit mode. Scroll reveals, counters, marquee and preloader turn off.
  5. Text and photosAll 67 strings and 12 photo slots, page by page, with reserved sizes. Two-line headings become one field each.
  6. ListsExecutives, events and sponsors: fields, add, drag to reorder, hide and remove.
  7. PublishUploads first, then rows, then deletes with storage first, as deleteContentItem already does.
  8. Settings and cleanupThe settings page, then delete the old dashboard tabs. /admin becomes the sign-in page only.
Edge cases

Open items

  • Proof needs content the club does not have yet. The sales sites above lead with reviews and customer counts. WSC has member counts and partner logos. Member quotes would need a small new table.
  • The length limits now set the layout. A limit that is too high makes a large empty field. Each of the 67 limits needs a check at phone width before step 5.
  • The owner account. It is the one account that cannot be removed. Ownership moves to the president in Settings when the maintainer leaves the club.
  • Two editors at once. If both publish the same field, the later one wins. Publish can compare update times and name the other editor later.
  • Hidden and past items. In edit mode they show in their real positions with a chip. In Preview they disappear.
  • The gallery has no page. Its admin tab goes away with the dashboard. The table and bucket stay.
